# 定义表 qualiscore

## 1 列契约

契约共 11 列；一次采信只处理模板**实际提供**的列（顺序即画像/单元格账的列顺序），
表头按别名映射（中文表头、带空格或括号都认），映射按列名不按物理位置，模板调整
列布局不会读错列。

| 列名 | 表头 | 类型 | 单位 / 刻度 | 取值范围 | 说明 |
|---|---|---|---|---|---|
| `ticket_id` | 工单号 | 字符串保形 | — | `T-YYYY-NNNNNN` 或 6-19 位数字 | 业务键；19 位大整数不过 `int()`；核心列 |
| `customer_id` | 客户号 | 字符串保形 | — | 3-8 位数字 | 前导零保留，`00123` 与 `123` 是两个客户；核心列 |
| `channel` | 渠道 | 枚举 | — | 电话 / 在线 / 邮件 / 门店 | 大小写与全角先折半角再比对；核心列 |
| `created_at` | 受理时间 | 时间 | 入库 UTC，展示 +08:00 | ISO8601 | 带偏移按偏移换算；无偏移按 +08:00；核心列 |
| `first_response_min` | 首响(分钟) | 小数 | 分钟 / 0.1 | 0 – 2880 | 千分位、全角数字先归一；核心列 |
| `handle_hours` | 处理时长(小时) | 小数 | 小时 / 0.01 | 0 – 720 | 同列混写小数位时按 0.01 量化；核心列 |
| `satisfaction` | 满意度 | 整数 | 分 / 1 | 1 – 5 | 1-5 分刻度粗，离散度低于 5 判退化；核心列 |
| `agent` | 受理人 | 文本 | — | 非空 | 旧模板列，与 `region` 常同起同落，看共缺对 |
| `region` | 区域 | 文本 | — | 非空 | 旧模板列 |
| `service_group` | 服务组 | 文本 | — | 非空 | 新模板把受理人+区域合并为本列 |
| `priority` | 优先级 | 枚举 | — | P1 / P2 / P3 | 不在枚举内记格式不合格；核心列 |

### 1.1 模板族与字段覆盖

渠道抽检附件混用两套模板，二者是同一字段族 `service_owner` 的不同布局：

| 模板 | key | 提供的服务归属列 | 列数 |
|---|---|---|---|
| 旧模板 | `legacy_v1` | `agent` + `region` | 10 |
| 新模板 | `service_v2` | `service_group` | 9 |
| 新旧混排 | `custom`（并集） | 三段成员都可能出现 | 11 |

- **字段族**：`agent` / `region` / `service_group` 同属 `service_owner` 族，
  族内任一成员列出现即视为该族覆盖，成员之间互不视为缺失。
- **核心列 `CORE_COLUMNS`**：8 个所有模板都必须提供的列（上表标注「核心列」）。
  核心列缺失或整字段族无任何成员 → `E_HEADER_INVALID` 422；族内新旧成员不做强制。
- **覆盖状态**：每列标 `present`（模板提供，参与三态与扣分）或 `absent`
  （模板未提供，标记 `K_TEMPLATE_COLUMNS_ABSENT`，不进缺失账、不进单元格总数、
  不扣分）。混排批次里某段缺列时，该段相关单元格记 `structural_missing`
  （原因码同为 `K_TEMPLATE_COLUMNS_ABSENT`），逐格豁免。
- **未登记模板**：表头映射出的列集合不匹配任何登记模板时记
  `K_TEMPLATE_UNREGISTERED`，按实际提供列继续评分；数据区出现另一模板的表头记
  `K_TEMPLATE_SWITCH` 并按分段处理，每段用各自表头取格，列数校验按段表头宽度。

## 1.2 双口径评分（可比性结论）

| 口径 | 分母范围 | 用途 |
|---|---|---|
| 有效口径（正式分） | 该批模板实际提供的全部列（剔除 absent / structural_missing） | 对本批数据负责，已提供列的真实空值、格式、重复、离群照扣 |
| 核心口径（可比口径） | 仅 8 个核心列，重复账用核心列哈希 `core_hash` | 新旧模板之间横向、纵向比较，规则与权重完全一致，只差列范围 |
| 朴素口径（只对照，不采用） | 把未提供列误当整列缺失 | 报告/导出中量化其虚高缺失率与虚扣分，说明为何不采用 |

- 两口径都满足 `总分 + 扣分 = 100`，权重、容忍度、量化方式相同；
  有效口径与核心口径的总分差完全来自模板专属列（服务归属字段族）的真实缺口。
- 只按共有字段评分会让新模板已提供列的真实缺口消失——该缺口保留在有效口径中；
  把未提供列当缺失则会制造模板切换的质量骤降——该虚扣在有效口径中被豁免，
  并在字段覆盖表（页面 + `coverage.csv` + `manifest.json`）中量化披露。

## 2 单元格三态

| 状态 | 判定 | 原因码 | 是否进缺失账 |
|---|---|---|---|
| 缺失 | 空串 | `K_NULL` | 是 |
| 缺失 | 空白串（只有空格、全角空格） | `K_BLANK` | 是 |
| 缺失 | 哨兵：`-` `--` `—` `/` `N/A` `NULL` `NONE` `未知` `无` `暂无` `待定` `空` `未填` | `K_SENTINEL_NULL` | 是 |
| 格式不合格 | 无法解析成该列类型 | `K_BAD_FORMAT` | 否，进格式账 |
| 格式不合格 | 能解析但越界（如满意度 7、首响 −3） | `K_OUT_OF_RANGE` | 否，进格式账 |
| 有值 | 解析成功且在范围内 | — | 否，进有值账 |

三条恒等式：

1. 单元格 = 缺失 + 有值
2. 有值 = 合格 + 格式不合格
3. 离群格 ⊆ 合格格（只从数值列、且该列未退化时产生）

优先级（TRAP-19）：缺失 > 格式不合格 > 离群。一个单元格只拿到一个状态与一个原因码。

## 3 时间

- 入库统一 UTC（`+00:00`），页脚与页面按 `Asia/Shanghai (+08:00)` 显示。
- `Z` 结尾、`+08:00`、无偏移三种写法都归一到同一时刻；无偏移按单据本地时区 +08:00 处理。
- 运行记录时间戳用 UTC ISO8601 秒级；表格里显示本地时间。

## 4 去重键

| 账 | 键 | 用途 | 与另一账的关系 |
|---|---|---|---|
| 全行哈希 | 10 列规范化后整行的 sha256 | 「采纳行 = 唯一 + 重复」 | 决定重复率与重复维扣分 |
| 业务键 | `ticket_id` | 同键重复、同键冲突 | 只做归因，不改变行账 |

- 缺失格参与哈希时用固定占位符 `\u0000MISSING`，避免「都缺这一列」被当成不同行。
- 格式不合格格用 `!` + 原值参与哈希，保证同一份坏数据两次运行哈希一致。
- 同键不同值：两行都保留原值，冲突列逐列列出；系统不猜哪条为准。

## 5 评分常量

| 维度 | 封顶分 | 容忍度 | 比率分母 | 说明 |
|---|---:|---:|---|---|
| 缺失 | 30 | 8% | 单元格总数 | 缺失格 / 单元格；分母只含模板提供列，absent/结构性格不计 |
| 重复 | 25 | 6% | 采纳行 | 全行重复行 / 采纳行；核心口径改用核心列哈希账 |
| 离群 | 20 | 10% | 参检格 | 离群格 / 参检格（已排除退化列）；数值列均为核心列 |
| 格式 | 25 | 5% | 有值格 | 格式不合格格 / 有值格 |

- 每维扣分 = 封顶分 × min(1, 实际比率 ÷ 容忍度)，量化 0.01（ROUND_HALF_UP）。
- 总分 = 100 − 扣分之和，量化 0.01，恒在 [0, 100]；`总分 + 扣分之和 = 100` 逐位成立。
- 等级：A ≥ 90、B ≥ 75、C ≥ 60、其余 D；等级标签依次为可用 / 待复核 / 需返工 / 不可用。
- 严重度 = 该维扣分 ÷ 该维封顶分：≥ 0.60 严重、≥ 0.30 警告、> 0 提示、0 通过。

## 6 稳健离群

- 中位数：偶数个取中间两值均值；`MAD = median(|x − 中位数|)`。
- `z = 0.6745 × (x − 中位数) / spread`，阈值 `|z| > 3.5`。
- MAD = 0 时 `spread = 0.6745 × IQR / 1.349`（等价于 `z = 1.349 × (x − 中位数) / IQR`）。
- `spread` 低于「列刻度 × 5」或 MAD 与 IQR 同为 0 → 该列判退化，标 `K_DEGENERATE`，不产生离群格。
- 参检样本少于 4 个 → 方法记 `insufficient`，同样不产生离群格。

## 7 缺失模式

- 连续缺失段：同一列按原始行序连续缺 ≥ 3 个单元格记一段，起止都用源文件行号。
- 缺失签名：一行里缺失列名的有序元组；同签名行数 ≥ 1 即进模式表。
- 共缺对：两列在同一行同时缺失 ≥ 2 行才记一对。
- 全空列：整列 100% 缺失，单独标出，不算「填充率低的列」。

## 8 运行记录

| 字段 | 含义 |
|---|---|
| `run_id` | `QS-<UTC 时间戳>-<4 位随机>`，一次运行一个 |
| `input_digest` | 文件名 + 文件字节 sha256 + 规则版本与阈值摘要 的 sha256 |
| `rules_digest` | 权重、容差、等级阈值、稳健系数的摘要 |
| `version` | 同名数据集自增版本号，陈旧提交靠它拦 |
| 幂等键 | (`数据集名`, `input_digest`, `rule_version`) 唯一，重复运行直接复用 |
| 模板兼容 | 模板注册表与字段覆盖属于采信层能力，不改动 `RULE_VERSION` 与摘要常量；整批重新运行命中同一幂等键，不新增版本、不丢记录，模板/列布局变化只体现在 `params.template` 与 `template_coverage` 快照中 |

## 9 原因码

完整清单见 `app/reasons.py`，前缀含义：`E_` 文件级失败（4xx，整批不落数据）、
`Q_` 行级隔离（进隔离区，带行号与原值）、`K_` 标记（不进隔离区，只留证据）。
